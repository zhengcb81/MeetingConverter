# MeetingConverter 整改发现

- MiMo 在读完整正文之后才标记已经收到响应，截断和超时落进原重试分支。翻译的独立重试同样会重发。两者复用 `ProviderExchange`，先记派发意图，收到响应对象后立即确认响应，再读正文。
- 运行信息在现有本地轮转日志记录，F4 继续提供原因和费用对账。合成请求与音频正文只经过本地传输替身。
- 核心流水线的旧类型判断要求具体备用引擎。结构化可选事件协议允许其他实现保留降级事实。反馈写失败的日志只记结构化异常及位置，保持原业务退出。
- 按原兼容行为，现有提供商响应前故障与 HTTP 错误的重试上限保留。当前测试证明已收到成功响应后查不到正文时零重发，实际账户用量不作推断。
- 独立复审发现 `urlopen` 直接抛出的 `HTTPError` 同样带有当前 HTTP 响应。原交换对象跳过了这个分支，导致尝试号丢失，翻译退避时响应仍打开。整改后 exchange 区分明确拒绝与已接受响应，并为二者记录同一次尝试的安全事实。拒绝响应正文无需读取。
- 日志同时保存 `projection_version` 和 `implementation_sha256`。后者是源文件名到原文件 SHA-256 的有序 JSON 的摘要，覆盖供应商交换、调用者、流水线及反馈记录实现。保留历史 `implementation` 字段供旧消费者兼容，它仍表示投影版本。
