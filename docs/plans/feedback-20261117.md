## 本仓边界

源音频与目标文本属于会议转换流程。本仓按实际请求模式判断期望交付的产物，原文、翻译、双语三个 writer 分别保有自己的原子写责任。用户关闭翻译时只有原文是正确的。一个翻译模式任务即使正常返回，目标对照文本未产生、段数不齐或显示上轮残留时都值得检查。输出格式、写入失败和外部引擎状态分别留在自己的步骤上。

输入引用来自本次调用与本仓合成音频/转录标识，记录至少包括工作模式、引擎是否真正启动、返回段数、写入/替换和消费者可读取的结果。取原生异常类别和脱敏详细错误，保留调用关联。引用旧文件时要辨明本次是否真的产出它；只有“路径存在”会把失败后保留的上一版误算作本轮成功。日志引用逻辑产物 ID，源音频、逐字稿正文、命令秘密和绝对物理路径留在原责任域。外部引擎缺少费用收据时保留 unknown。

## 接口、问题卡和修复技能

通过可选 RESEARCH_FEEDBACK_OUT、RESEARCH_FEEDBACK_RUN_ID 和 RESEARCH_FEEDBACK_ATTEMPT_ID 向独占的本次 UTF-8 JSONL 目的地导出。每行 schema_version、owner、run_id、attempt_id、step_id、check_id、expected、actual 是稳定字符串；可选 issue_key、evidence_ref、version、parent_step_id、details_ref、disposition（expected/deviation/unknown）、origin_owner。避免在既有机器可读输出流混入新行。侧车 I/O 失败保留可读诊断，不重做转录和模型调用。

~~~json
{"schema_version":"feedback-observation/1","owner":"meeting-converter","run_id":"mc-offline","attempt_id":"a2","step_id":"publish","check_id":"requested-outputs","expected":"bilingual_current","actual":"previous_version_only","disposition":"deviation","issue_key":"stale-output-success","evidence_ref":"mc:synthetic/publication-2"}
~~~

维护 issues/feedback/ 中可版本化的根因记录或引用已有记录。问题卡包含复现命令、预期/实际、运行引用、影响的输出模式、回归测试、修复及消费方验证版本。一次运行多次观察使用同一 run、尝试、步骤和检查引用，重复输入应关联原 issue。修复技能放在 skills/repair-meeting-converter-issue/SKILL.md，只改本仓，依次定位首次错误的边界、从最小合成片段复现、把需要的结构改动写入本仓 PWF、先失败再修复、给出原模式和相似合法模式的对照。下游展示的故障交给相应 owner。状态从已发现、处理中推进到已实测修复；测试失败时既有发布物保持原样。

## 实施、复验和交接

1. 以 tests/test_transcribe_integration.py 的 mock engine、原语言/翻译路径及 tests/test_output.py 的合成 Paragraph/Segment 和错误注入为基线。事先写出原文模式、翻译完整、段数失配、旧文件保留、渲染或替换失败的期望。加入零退出却缺本轮产物的反例，并用关闭翻译的正确缺件作对照。录制真实公开接口的输入输出，分别从期望模式和实际产物导出状态；避免从同一变量同时填充 expected 和 actual。
2. 在本仓流程或 writer 结束边界接入观察器。保留 fallback、停在处理过程中和引擎未启动的区别。侧车只在真实终态之后投影，逐字稿写入、stderr、异常和控制命令保持本仓权责。每个尝试有独占输出，不从工作进程重写其他尝试历史。
3. 模拟无法保存诊断、重读同一条已完成记录及外部调用后结果未知。检查各次任务费用/启动计数，验证诊断重放不会重新转录。修复技能只基于已证明的故障建卡。用另一个语言/合成片段证明泛化，模仿旧输出时不删除已有用户文件。
4. 仅在本次独占的 tmp_path 中写合成音频、输出和 JSONL，并在 finally 中清理。pytest.ini 默认开启覆盖率报告；复验时显式清除 addopts 或把 COVERAGE_FILE 指向本次独占临时目录，确保 checkout 中原 .coverage 按字节保留。下列测试包连同新增观察用例构成一次本仓大节点。无需调用真实服务。

~~~text
python -B -m pytest -o addopts= -q tests/test_output.py tests/test_transcribe_integration.py
~~~

交接前让独立 reviewer 依据真实公开回放、业务产物内容与错误注入复核，修完所有发现后再提交。交接内容包括 owner/工作目录、base/implementation/reviewed SHA、执行模式/调用办法、逻辑证据、实际测试与清理、是否复用或重跑引擎、待接收方验证范围。早期施工安排接续总控首轮反馈试点。
