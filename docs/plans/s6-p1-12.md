# MeetingConverter S6 Phase 1

The owner suite is discovered from the complete tests directory. Ubuntu and Windows use the
same receipt collector and test scenarios for the exact Git commit. The two native-only file
and process tests run on Windows. Provider calls in this suite use loopback fixtures.

A development pass can run:

```text
python -m pytest -q tests/test_config.py tests/test_ci_workflow_config.py tests/contract
```

For the production transcription CLI, `--config <path>` selects that JSON file. Relative paths
resolve from the caller's working directory. Command flags retain higher precedence than the
selected config. A missing/malformed explicit config ends the run before dispatch. If no
`--config` is given, the existing adjacent configuration behavior is preserved.

The native audio/loopback cases in `tests/test_native_cli_e2e.py` require `ffprobe` on PATH.
They take a WAV through the actual command, verify CLI override, reject malformed input before
provider dispatch, and cold-read a truncated response using the original meeting operation.
Windows and Ubuntu Actions provision the probe only if unavailable. Daily local tests do not
trigger deployment or the two-platform matrix.
