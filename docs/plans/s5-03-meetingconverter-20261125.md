# MeetingConverter S5 审计复核

以本仓已发布的 `master@9a96ecfdc4a25a55615da78e28af92f91874b898` 为基准。使用独立工作树与合成数据。现行 CI 用 Python 3.13 收集 `tests/`，新增用例沿用该入口。本机 F4 的本仓命令仍以原主工作区为 cwd。

## 逐项复验

| 审计项 | 原入口证据 | 修复与对照 |
|---|---|---|
| 省略引擎参数 | 配置选 Whisper 且填入合成 MiMo key 时，实际 CLI 误调用 MiMo 替身 | 文件引擎生效。显式 `--engine auto` 继续按原逻辑选 MiMo 或 Whisper。 |
| 参数优先级 | 明示模型、设备和精度时，三项均被反向覆盖 | 显式参数优先。只读一次原配置，未显式设置项沿用其值。 |
| 实际入口校验 | 布尔型重试数和段落间隔通过原配置校验。翻译入口曾收下非法配置并发起替身请求 | 按转写公共字段及已选提供方校验。同一 CLI 错误下原文仍走所选 Whisper 设定，翻译请求数量为零。旧文档中允许 `0`，现在正确执行单次首请求，正整数的既有尝试总数保持。 |
| ffmpeg 与原件守护 | 静音检测或切片非零仍返回临时件。零字节切片可进入编码。一个以 `mimo_chunk_` 开头的原件在直接返回原路径时被清理 | 识别两阶段失败，异常时同时清理先前和当前生成件。零字节切片返回错误。指定合成原件字节不变。 |
| MiMo HTTP 资源和响应 | 人工 HTTPError 的二进制流在退避时仍未关闭。已完整读取的坏响应造成三次合成 POST | 退避前关闭错误响应。完整读取后的解析或形状错结束本次上传，尝试数为一。已验证的 503 回退及用量语义沿用。 |
| 公司上下文 | YAML 空条目在纠错与别名路径抛出 AttributeError。管理 CLI 拒绝读取端已有的定位和板块参数 | 共用本仓 YAML 入口，空映射可读。管理 CLI 支持添加和更新定位、板块，普通转写读取同一持久值。 |
| 本地日志试点 | 普通 CLI 的合成底层失败没有可冷读文件，批处理 stderr 曾打印异常正文 | 转写 CLI 写入本仓状态根下的 `logs/transcribe.jsonl`，按 1 MiB 轮转并保留两个历史文件。记录原运行及尝试、阶段、类别、原因链和本仓源码位置。目录或文件写失败时向 stderr 发送短告警，保留原有退出码和生产结果。 |

## 验证范围

- 使用断网替身的 CLI 复验，合成音频、提供方响应、错误响应流及临时输出都在独占目录。测试未调用真实服务。
- Windows 本仓全量 386 项通过，按常规 CI 覆盖率命令复跑为 95.40%。随后新增无 stderr 的宿主复验，确认写入失败告警保持 stdout 安静。测试同时覆盖正反对照、文件轮转、无权限日志目录、F4 侧车冷读和原件留存。
- 原自动临时根较长时，既有一项 F4 测试未读到终态。使用明确短的隔离测试根，该用例和全量测试均通过。
- 日志改造当前覆盖转写实际入口及其调用链。控制查询、公司管理和引擎对照工具的本地日志范围留待分项复核。多进程同时写一份日志的轮转未作保证，发生写失败时仍保留 stderr 告警及既有反馈渠道。
- 对具体 `FallbackEngine` 类型的反馈依赖和 `core/feedback.py` 的结构拆分属于后续仓内架构项。

此候选由独立审查后交付发布和正式运行验收。未修改本机正在使用的主工作区和 F4 配置。
